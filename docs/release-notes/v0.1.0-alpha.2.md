Second alpha. No change to what the application does. This release makes Nyctr deployable from a GitOps cluster repository and makes releases automatic.

Still a prerelease, and still true: nothing in it has been run against a real UniFi console, NextDNS profile, Proxmox cluster or Pi-hole.

## What changed

- **The Helm chart is published.** Each release now pushes the chart to `oci://ghcr.io/homelab-0/charts/nyctr` under the release version, so Helm and Flux can install it without cloning the repository. The chart never chooses an image: set `image.digest` to the digest listed under Artifacts.
- **A trusted proxy range.** `forwardedAllowIps` accepts a bounded range such as `10.42.0.0/16` (no wider than `/16` for IPv4 or `/48` for IPv6), but only while the chart's network policy is on. Gateways whose proxy pods change address on restart no longer need an exact list.
  The policy being on is necessary, not a guarantee. Every peer in the range that can connect is believed, so make sure `ingressFrom`, and any other policy selecting the pod, admits only your proxies. Otherwise use exact addresses.
- **Releases are automatic.** Merging a version change to `main` publishes the image, the chart and this release. Nobody creates a release by hand. See [docs/releases.md](https://github.com/homelab-0/nyctr/blob/main/docs/releases.md).

## Installing the chart

```sh
helm upgrade --install nyctr oci://ghcr.io/homelab-0/charts/nyctr --version 0.1.0-alpha.2 \
  -n nyctr --create-namespace -f nyctr-values.yaml --wait --timeout 5m
```

A Flux `OCIRepository` outline is in [charts/nyctr/README.md](https://github.com/homelab-0/nyctr/blob/main/charts/nyctr/README.md).
