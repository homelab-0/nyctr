Fourth alpha. Two fixes, no new features and nothing to configure.

Still a prerelease. Neither fix was run against a real identity provider or a real DNS source before this release; see "Not verified".

## What changed

- **An administrator lands on the Briefing after single sign-on.** The sign-in callback used to send administrators to a page the console does not have, so the first thing they saw was "This screen could not be found". It now sends them to the console without naming a page, and the console opens its first screen, the Briefing. Where a member lands is unchanged, and so is the move to the portal address when one is set.
- **A busy DNS source is collected, not refused.** One collection reads at most 4,000 blocked lookups from a DNS source (20 pages of 200). A source with more than that in its time window used to fail the whole collection and store nothing, so with the default 24-hour window a busy network never collected at all. Nyctr now keeps the most recent lookups up to the same limit and says the collection is partial:
  - the source is stored with the status `partial`, not `error`;
  - the source card, the Briefing and the message after "Collect snapshot" say that only the most recent blocked lookups were read;
  - the collection's audit record carries `partial` and the number of rows kept, and the collect response has a `partial` field.

  The limit itself has not changed, and older lookups in the window are still not read. Any other fault still fails the collection and stores nothing.

## Upgrading

- No database schema change. Upgrading from v0.1.0-alpha.3 runs no migration and needs no new setting.
- `partial` is a new value in the existing source status. If you go back to the v0.1.0-alpha.3 image, a source stored as `partial` is shown as collected, without the note.
- The image is `v0.1.0-alpha.4` and the chart is `0.1.0-alpha.4`, the same pairing as before.

## Validated

With fabricated data only, on one Linux x86-64 machine:

- The API, console, release and acceptance-helper test suites, the console build, and the chart tests with Helm 3.22.1.
- The image built from this source and started in Demo mode. In headless Chromium, signed in as the demonstration administrator, the console showed the Briefing with the title "Briefing · Nyctr" at `/#/` and at an address with no fragment, the old landing address `/#/overview` showed the not-found screen, and the Sources page and the Briefing loaded without a failed request or a console error.
- The isolated acceptance stack (`tests/acceptance`): the production image against a fabricated network controller and DNS service, including the restart persistence check. Signed in there in the same browser, the Briefing and the Sources page loaded without a failed request or a console error.

## Not verified

- **The landing after single sign-on against a real identity provider.** Tests cover the redirect the server sends and what the console shows at that address. The full round trip through a real provider is checked on a running installation after the release.
- **A collection against a real DNS source that exceeds the limit.** Tests use a fabricated log longer than the limit. The fabricated DNS service in the acceptance stack has one blocked lookup and never reaches it.
- The chart with Helm 4, and an installation of the chart in a cluster, were not run on that machine. CI runs both for this release.
- Everything listed under "Not verified" in earlier releases still applies, including the proxy range limitation described in v0.1.0-alpha.3.
